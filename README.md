# Loquilis

**Your agents, in a real window.**

Loquilis is a desktop console for conversations with AI coding agents. It drives the agents' own headless modes and puts a real GUI on top of them. Today it runs Claude Code, Grok, and OpenCode with a local model, plus plain chat with a local model through a runner such as Ollama. Codex and others are to follow. The name comes from the Latin *loqui*, "to speak, to converse".

Loquilis records every turn of a conversation, from both sides, along with every command the agent runs along the way. All of it is stored on disk. You can view the same conversation in different ways and switch between them at any time:

- **Messages:** speech bubbles, with you on the right and the agent on the left. Each turn's work folds into a "Ran 18 commands" line that opens on demand.
- **Tree:** the conversation as a structure of turns and tool calls. Branches are modeled, and their view comes later.
- **Search:** full-text search across every conversation and every command.

## Terms

A few names from Plusauri's other work appear in this repo:

- **Tutilis** is Plusauri's retirement-planning desktop app. It is not open source. Loquilis was designed with its conversation needs in mind, and it does not depend on it.
- **Cogilis** is Plusauri's agent workspace for Tutilis: an AI coding agent that answers questions about a Tutilis lesson plan using Tutilis's own tools. Its recorded sessions are public teaching material.
- A **take** is one recorded agent session, kept as a folder holding `conversation.json` (the recorder's summary) and `raw.jsonl.gz` (the agent's stream, as it arrived). The test fixture and the bundled sample are a Cogilis take.

## Library first

Loquilis is built almost entirely as a library, **`loquilis`**, with a thin application on top. The plan is for the library to be the starting point for your own agent console: keep the model, storage and views, and add your own functionality.

| Module | What it holds |
|---|---|
| `loquilis-model` | The conversation model, defined in protobuf (`loquilis-model/protobuf/`) with Kotlin generated by Wire. It has no UI or agent dependency. |
| `loquilis-store` | Disk-backed storage. Conversations are paged in on demand and never have to fit in memory. |
| `loquilis-agents` | One parser and one session for each kind of agent. Each turns the agent's event stream into model entries. |
| `loquilis-views` | The Compose views (messages, tree, search) over the model. Each can be skinned. |
| `app` | The Loquilis desktop app, kept as thin as possible. |

Built with Kotlin Multiplatform and Compose Multiplatform, for desktop first.

## Dependencies

Loquilis has no dependency on Plusauri's other products, apart from the published ui-kit ([plusauri/ui-kit](https://github.com/plusauri/ui-kit), `com.plusauri:ui-kit` on Maven Central). See `doc/decisions/0001-dependency-direction.md`.

## Status

Early. The model, the storage and the views work, but nothing here is a stable API yet: a module's shape can change from one commit to the next.

The window is developed and tested on macOS. Linux and Windows are untested.

## Building and running

You need JDK 17 or newer. No account or token is needed: every dependency, the ui-kit included, comes from Maven Central.

```
./gradlew :loquilis-model:jvmTest :loquilis-agents:jvmTest :loquilis-store:jvmTest :loquilis-views:jvmTest :app:jvmTest
scripts/run-loquilis.sh --sample     # the bundled sample conversation
scripts/run-loquilis.sh              # your own library of conversations
```

Sending a message runs the agent's own command-line tool, so `claude`, `grok` or `opencode` must be installed and signed in. A local model needs a runner such as Ollama.

When Claude asks to use a tool and you answer "Always allow", Claude Code writes that rule to `.claude/settings.local.json` in the folder you chose for the conversation. Expect that file to appear there.
